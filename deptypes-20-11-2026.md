## How far it goes

All dependent-type handling is controlled by one flag, `opt_dependent_types`, which is on by default (`coq_transl_opts.ml:56`). Turning it off restores the earlier translation, where indexed inductives stay opaque and their eliminations are not erased.

**It is not limited to particular named types.** The classifier decides how to treat an inductive from the shape of its declaration, for any inductive. Only a few standard constants are handled by name: the `eq_rect`/`eq_ind` transport family, `False_rect`, the proof terms `eq_refl`, `eq_sym`, `eq_trans` and `JMeq_refl`, and the well-founded recursion combinators `Fix`, `Fix_F` and `Fix_sub` together with the `proj1_sig`/`exist` reductions.

**Only five shapes get a precise encoding.** Everything else is translated soundly but loosely:

| Class            | Shape                                                                                                | Examples                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `CEmpty`         | no constructors                                                                                      | `False`                                                                              |
| `CPropSingleton` | a `Prop` type with one constructor whose fields are all proofs                                       | `True`, `and`, `eq`, `Acc`                                                           |
| `CSubset`        | a non-`Prop` type with one constructor: one data field (the "carrier") plus at least one proof field | `sig`, `sig2`, `{n \| 0 < n}`-style records, indexed subsets                         |
| `CEnum`          | a non-`Prop` type in which no constructor has a data field left after fording (below)                | `bool`, `sumbool`, `reflect`                                                         |
| `CRegular`       | everything else                                                                                      | `Vector.t`, `Fin.t`, `sigT` with a data second component, non-singleton `Prop` types |

There are side conditions:
- A `CSubset` carrier must not be a sort or reach the inductive itself (directly or through other inductives).
- A proof field may not depend on another erased proof, and the carrier may not be the head of a proof's type.
- An *indexed* subset whose fields depend on its parameters is demoted to `CRegular`.

`CRegular` types still benefit inside matches (fording and branch pruning, below). Their type guard, though, stays a plain membership atom, `$HasType(x, ⟦I p̄ ī⟧)`.

**Known limits:**
- The translation is deliberately shallow. A subset type is expanded where it occurs; no axiom relates `sig A P` to its carrier.
- Dependent products have no shared symbol. Each one becomes a lifted `$_type_N` symbol with a one-way unfolding axiom.
- Type-level computation is resolved only by head reduction limited to 64 steps (`opt_whnf_budget`).
- When a shape can't be decided, the translation falls back to the coarser treatment or omits the equation. This costs completeness, never soundness.

On the 7-corpus evaluation, #234 recorded zero consistency hits and a slight net loss on attempts that both versions ran (516 gained, 814 lost).

## The translation

Notation: `⟦t⟧` translates a term, `G(x : T)` is the FOL formula ("guard") saying `x` has type `T`, and `I p̄ ī` is an inductive applied to parameters `p̄` and indices `ī`.

**0. Base translation (unchanged).** Coq is translated to untyped FOL. Types become guards. A binder over a proposition becomes an implication. Proofs become `$Proof` and are dropped from argument lists. Lambdas, fixpoints and matches are lifted to fresh symbols with defining equations.

**1. Classifying an occurrence of `I p̄ ī`.**
1. Head-reduce the type within the budget and require `I` to be fully applied.
2. Compute the *informative mask*: which index positions are not propositions.
3. **Fording** (`ford_indices`). For each constructor `c : Π ȳ. I p̄ ū`, look at each informative index position `j`:
   - If the pattern `u_j` is just a constructor argument `y` that hasn't been solved yet, `y` is *solved*: it is replaced by the index (`y := ī_j`) instead of being quantified.
   - Otherwise the position contributes a *residual equation* `ī_j = u_j`.
4. Split the remaining fields into proofs (type in `Prop`) and data. Then pick the class from the table above.

**2. Guards for a type occurrence (`guard_leaf`).** Let σ be the substitution: carrier ↦ `x`, each solved `y` ↦ `ī_j`, each proof ↦ `$Proof`.
- **`CSubset`:** `G(x : A σ) ∧ ⋀ ⟦P_k σ⟧ ∧ ⋀ (ī_j = u_j σ)`.
- **`CEnum`:** a disjunction over constructors: `⋁_c ( x = ⟦c p̄ ȳσ⟧ ∧ ⋀ ⟦payload_c σ⟧ ∧ ⋀ index-equations_c )`.
- **`CEmpty`:** `⊥`.
- **Otherwise:** `$HasType(x, ⟦I p̄ ī⟧)`.
- **Dependent product `Πx:A. B`:**
  - If `A` is a proposition: `⟦A⟧ → G(f : B)`. Arguments of proof type are dropped, so `f` is not applied.
  - Otherwise: `∀x. G(x:A) → G(f x : B)`.

**3. Terms.**
- A subset constructor application `c p̄ … a …` translates to `⟦a⟧`, the carrier, keeping any further arguments. If it is not applied to all its arguments, it is eta-expanded and lifted.
- A transport `eq_rect A x P f y e` translates to `f`.
- In `False_rect T …`, the type argument `T` is replaced by `$Any` when it contains a type that gets expanded or erased.

**4. Matches.** Suppose a lifted symbol `f(v̄)` matches on a variable `z : I p̄ ī`:
- **The match returns a proposition.** `f` is a predicate with two axioms:
  - lower bound: `inh ∧ ⋀_c ∀args. (z = c… ∧ idx-eqs → B_c) → f(v̄)`
  - upper bound: `inh ∧ f(v̄) → ⋁_c ∃args. (z = c… ∧ idx-eqs ∧ B_c)`

  Here `inh` is the guard (or formula) for the scrutinee's own type.
- **The scrutinee is a proof and the result is data.**
  - `CPropSingleton`: the match is replaced by its one branch with proofs erased, and needs no premise. This is how `eq` and `Acc` eliminations disappear.
  - `CEmpty`: no axiom is emitted.
- **A non-indexed `CSubset`:** the branch is used with carrier := `z` and proofs := `$Proof`.
- **Otherwise** (enums, regular types, indexed subsets), one equation per constructor:
  `∀ (v̄ ∖ z) args'. f(v̄)[z := c p̄ s̄] = B_c s̄`
  - `s̄` is the argument list after fording at the scrutinee's actual indices, so a solved argument becomes `ī_j` and is not quantified.
  - A branch is pruned when an informative index pattern has a different constructor head from the actual index (`rigid_clash`).
  - If an indexed subset has solved arguments but its indices can't be read from the scrutinee type, the equations are omitted. Emitting them would leave a binder free on the right-hand side, which is unsound.
- **The scrutinee is not a variable:** the match is lifted into a helper function, and a `$link` equation connects it to `f`.

**5. Declarations.**
- Injectivity, discrimination and inversion axioms (inversion includes index equations) are kept, except for a declaration that is a `CSubset` everywhere and does not depend on its parameters. That one has no constructor symbol left to describe.
- A constant whose type contains a subset or enum gets its `$_typeof_` axiom built directly from the guards in §2, so the expansion happens at each use. For a function type it also states that the constant belongs to its own type.

**6. Well-founded recursion.** `Fix`, `Fix_F` and `Fix_sub` produce unfolding equations that keep their `Prop` premises, for example `b ≠ 0 → idiv … = …`. They are never unconditional.
